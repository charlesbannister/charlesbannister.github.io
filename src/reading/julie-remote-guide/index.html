Julie Remote: how it works

A plain-English guide. Written 25 November 2026.

What it is

Julie Remote lets you work with Julie (Claude Code plus all your Julie rules) from anywhere: your phone, this Mac, or any browser. The work itself never runs on the Mac. It runs on one of two other computers:

  • The Windows laptop at home. It is used first whenever it is switched on.
  • A server on Amazon Web Services (AWS). It is used when the laptop is off. It switches itself on when there is work (about a minute) and off again after 30 quiet minutes, so you only pay while it is busy.

Because the work runs elsewhere, you can close the MacBook, lose your internet connection, or put your phone away, and Julie keeps going. When you come back, the whole conversation is waiting for you in every place.

The three ways in

1. The website (phone or computer)

Open julie.shabba.io and sign in. On your phone, use "Add to Home Screen" so it behaves like an app.

  • The home screen shows your starred projects at the top, then every project, most recent first. Anything untouched for 30 days is tucked away behind a "Show older" row. Tap the star to pin a project.
  • Tap a project to see its chats, or press + New.
  • Tap the microphone, speak, and tap again to stop. Your words appear in the box (transcribed by OpenAI) ready to edit and send.
  • The two dots at the top show whether the laptop and the server are on. You can start or stop the server by hand there too.

2. The Mac terminal

Your usual shortcuts now talk to Julie Remote instead of running on the Mac: j, adevolver, aedataclaude, k, ko, shabba, ddl, pixel, trivia.

  • Type a message, watch the work happen, type the next one. An empty line leaves; the work carries on.
  • Add -c to continue your latest chat in that project, including one you started on your phone.
  • Add --aws or --laptop to choose the machine.
  • The old local versions still exist as j-local, k-local and so on, for when you want the full Claude Code screen on the Mac.
  • jr on its own lists the extra commands (list chats, follow one live, stop one).

3. Anywhere else

Any browser on any device works the same as the phone.

How it works underneath

There are four small parts:

  1. A front door on AWS. A tiny program that only runs when someone uses it. It serves the website, checks your password, and keeps a list of chats and messages in a small database.
  2. A worker on each machine. Every few seconds the laptop and the server ask the front door "is there anything for me?". If there is, they run it with Claude Code and send each step back as it happens. Because the machines ask rather than wait to be called, nothing at home has to be opened up to the internet, and the laptop works from any network.
  3. Choosing a machine. A new chat goes to the laptop if it has checked in within the last 45 seconds; otherwise to the server, which the front door switches on. A chat stays on the machine it started on, because Claude keeps that conversation's memory on that machine.
  4. GitHub as the shared filing cabinet. Every machine keeps its copies in step with GitHub (see the next section).

Claude runs on your Claude subscription on both machines (the laptop through its normal login, the server through a long-life subscription token), not on paid API credits.

Keeping everything in step

  • Plans, notes and status pages (the "homes") are saved and sent to GitHub automatically after every Julie turn on the laptop or server, and every five minutes. The Mac already does this every ten minutes. A secret scan runs first, so passwords and keys are not sent.
  • Code is never saved automatically behind your back. Instead, Julie is told: when you change code, commit it and push it before you finish. If she is on a branch that deploys (main, staging, production), she puts the work on a separate julie/… branch and tells you.
  • Before every turn the machine downloads the latest Julie rules, notes and the project's code.
  • Every few minutes each machine, including this Mac (new, every ten minutes), quietly brings its code copies up to date, but only when that copy has no unsaved changes. It never merges or overwrites work.

In practice: work started anywhere shows up everywhere within a few minutes. The one thing to remember is that a code change on the Mac only reaches the other machines once you (or Julie) commit and push it.

What you need to know to use it well

  • Leave the laptop plugged in. It is set never to sleep on mains power, even with the lid shut. On battery it may sleep, and work then moves to the server.
  • One chat, one machine. If a chat is waiting for an offline laptop, press "Run on AWS instead". It starts a fresh conversation there, so add a line of context.
  • Julie works unattended. She does not stop to ask permission for each step, just as with your local shortcuts. Your safety rules still apply (no releases, production changes or secret files without your say-so).
  • Projects: every repository on your GitHub account is available. The first use of one downloads it, which can take a minute for big ones. Folders that exist only on this Mac are not available remotely until they are put on GitHub.
  • Cost: the website and database cost pennies. The server costs about 7 US cents an hour while switched on, plus about $5 a month for its disk. Dictation costs about half a cent per minute of speech from your OpenAI balance.
  • Your password is in the email you were sent. Signing in keeps you logged in for 30 days on that device.

Sources and similar projects

Other people solve the same problem in three main ways. I looked at these and chose the third, because it needs no tunnels, no accounts with extra services, and works when the Mac is off:

  • A web interface on the machine itself, reached through a tunnel, for example CloudCLI / Claude Code UI with a tunnel service as described by Pinggy, or Tailscale plus SSH and tmux.
  • Anthropic's own Remote Control (claude remote-control), which links a running session to the Claude app on your phone: see DataCamp's walkthrough and Builder.io on Claude Code from a phone. It needs the session to have been started on a computer first.
  • Running Claude Code "headless" and building your own front end around it. This is what Julie Remote does, following Anthropic's documentation on headless mode and streamed output and on signing in with a long-life subscription token.

The phone-app layout (starred items, then recent ones) copies the Claude app. Dictation uses OpenAI's transcription service.

What we could improve next

  • Notifications: a phone notification (or Slack message) when Julie finishes or needs you.
  • Move a chat between machines with its memory, by copying the conversation file across, instead of starting fresh.
  • Attach files and screenshots from the phone to a message.
  • Live previews: a link to see a web app Julie is building, running on the laptop or server, from your phone.
  • Answer Julie's questions with buttons rather than typing.
  • Stronger sign-in: a passkey or Google sign-in instead of a password.
  • Put the remaining Mac-only folders on GitHub (Smith, Shabba Connect, find-a-job and others) so they work remotely too.
  • Use Anthropic's Remote Control alongside this, so the official Claude app can also join a running session.
  • A small cost and usage view showing server hours and dictation minutes.
