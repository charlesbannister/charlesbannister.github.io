AdEvolver V2: what's left before beta

Since yesterday afternoon a full review was done and its fixes committed: security, AI cost limits, reliability, backups and speed. None of it is on production yet. Production is still the 23 November release 9fe2438, and the extra email editor entries are still uncommitted. The same four things stand between V2 and its first beta team: most copied users can't receive email, nothing yet stops Classic alerting a team that has moved to V2, nobody outside the team has been through it end to end, and V2's code exists only on your Mac. That last one got worse: the disk is now full, with 2 GB free. My estimate is still one and a half to two days, plus a release of last night's work.

Recommendation

Unchanged: run a small, invite-only beta first, and keep it read-only for the first week.

  • Who: five to ten existing paying agency teams from the users already copied across.
  • How they get in: public sign-up stays paused. You switch each beta team's V2 access on, then show them the Classic banner. The banner's Continue link already carries them through sign-in to the V2 welcome.
  • What they can do: everything except send changes to Google Ads. After a clean first week, switch changes on one account at a time.
  • Price: free during the beta. Stripe stays in test mode.
  • One app in charge per team: a team on V2 gets V2's alerts only; Classic's pause until they go back. This is now the main thing to build.

Where V2 is now

  • Live at v2.adevolver.com, release 9fe2438 (checked November 24), health check answering. Two newer commits are waiting. Classic is live at d35cf22 with the beta banner switched off.
  • Users copied from Classic: 167 users and 1,529 accounts, a one-time copy at 02:51 UTC on November 23. Anything changed in Classic since is not in V2.
  • Google sign-ins: 27 of 48 copied sign-ins work in V2. The other 21 users must reconnect Google Ads. Today's release also makes V2 drop a cached Google token that Google refuses and retry once.
  • Tested on production with one real account: 25 of 27 tools ran (the other two need chat input or Search Console). A change round trip worked.
  • Who can get in: sign-ups paused on both apps. Each team's V2 access is closed by default; only your own team is open.
  • Safety settings: email live, Slack off, Stripe in test mode, Google Ads writes allowed for one test account, change approvals off.
  • Welcome video: the V2 welcome shows "walkthrough coming soon" until you record it and set the link.

Emails

Sending is in good shape. Amazon SES has production access (50,000 a day), adevolver.com passes DKIM and publishes DMARC, and every V2 email goes through one sender that honours bounces and complaints.

The problem is still who can receive it. Alert, Guard, Feed, dashboard-ready and Budget Commander emails, and accepting a team invitation, all need a verified address. Only 31 of the 167 copied users have one. Signing in with an emailed code doesn't count as verifying, although it proves the same thing. Changing that would quietly fix most of the gap for anyone who signs in by code.

Switched off on purpose

Known problems

  • Work not released: two commits from the full review (102 files) and 21 uncommitted files for the extra email editor entries. Tests for the email work pass locally (111). Both need a release.

Before beta: the list

  1. Push V2 to a private GitHub repository and free disk space on the Mac. Ten minutes, and it removes the worst risk.
  2. Release last night's review fixes with the email editor entries (commit those first).
  3. Build the per-team Classic alert switch. Moving a team to V2 pauses its Classic alerts and Budget Commander and sends the V2 welcome; going back reverses both and sends the confirmation.
  4. Fix email for copied users: count a code sign-in as verification, and send a verification link with each beta invitation. Accepting an invitation already verifies (unreleased).
  5. Read every email. Use the email reading copy, change wording in the editor, then send each one to Gmail, Outlook and Apple Mail.
  6. Open the ad-group report and the six Guard checks to confirm last night's data run produced them.
  7. Test a Google reconnect on V2 with a login other than yours.
  8. Record the walkthrough and set its link, or leave "coming soon".
  9. Walk one real manager through it while you watch: banner, sign in, welcome, dashboard, an alert email, investigate.
  10. Housekeeping: push the data-platform commits, rehearse a database restore.
  11. Open the beta teams one or two at a time and watch each team's first night.

During the beta

  • Week two: changes. Add beta accounts to the change allowlist one at a time and switch change approvals on for beta users only.
  • Billing. Run checkout, renewal, failed payment and cancellation end to end in Stripe test mode before V2 charges anyone.
  • Measure where people stall: sign-in to first dashboard, first alert opened, first finding reviewed.
  • Later: Search Console once Google approves, "Sign in with Google", then reopening public sign-up.

Decisions for you

  1. Beta cohort: five to ten paying agency teams (recommended), or every copied user.
  2. Changes in week one: off (recommended), or on for chosen accounts.
  3. Price: free during beta (recommended), or charge through V2.
  4. Verifying copied users: count a code sign-in plus a link with the invite (recommended), or mark beta users verified by hand.
  5. Classic Budget Commander for beta teams: pause it with Classic alerts (recommended), or keep it running until V2's is trusted.
  6. Classic daily store: switch Classic to the live store. This needs a Classic change.
